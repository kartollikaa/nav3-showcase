# Navigation 3 Showcase

Учебный репозиторий для внутреннего доклада по мобильной разработке на тему **Jetpack Navigation 3 (Nav3)**.
Всё построено на **Jetpack Compose**. Репозиторий организован как набор git-веток, каждая из которых дополняет предыдущую — можно выполнять `git checkout` прямо во время доклада и запускать `git diff` с предыдущей веткой, чтобы показать *только то, что изменилось*.

> Актуальность проверена по официальной документации (developer.android.com/guide/navigation/navigation-3) по состоянию на **июнь 2026 г.** Ядро Nav3 стабильно, версия **1.1.2**. См. [`gradle/libs.versions.toml`](gradle/libs.versions.toml).

---

## Суть в одном абзаце

В Navigation 2 фреймворк **владел** вашим бэкстеком: навигация осуществлялась через строки маршрутов, а `NavController` мутировал скрытое состояние. В **Navigation 3 вы владеете бэкстеком** — это обычный наблюдаемый `List` из типобезопасных ключей. Переход вперёд — это `backStack.add(key)`, возврат назад — `backStack.removeLastOrNull()`. Единственный composable-компонент, **`NavDisplay`**, наблюдает за этим списком и отображает верхнюю запись. Всё остальное (нижние листы, многопанельный режим, диалоги, привязка ViewModel к области, анимации переходов) подключается как *стратегии сцен* и *декораторы* — опционально, компонуемо и прозрачно.

## Карта веток

Две независимые ветки, обе ответвляются от `main`. Внутри каждой ветки каждая последующая ветка строится на предыдущей.

### Flow 1 — Введение (нарастающая сложность)

| Ветка | Что добавляется |
| --- | --- |
| `flow1/01-basics` | Простейший Nav3: собственный бэкстек + один `NavDisplay`, типобезопасные ключи, без сцен и DI. |
| `flow1/02-scenes` | Сцены: стратегия оверлея **нижнего листа** и сцена **многопанельного списка с деталями**, адаптирующаяся к ширине экрана. |
| `flow1/03-viewmodel-decorator` | `rememberViewModelStoreNavEntryDecorator` — привязка ViewModel к области отдельной записи и демонстрация того, что ломается без этого. |
| `flow1/04-animations` | Анимации переходов для всего экрана **и** для отдельной записи: один общий `transitionSpec` для всего графа и его переопределение для одной записи через метаданные (включая предиктивный жест «Назад»). |

### Flow 2 — Миграция (Fragments + Nav2 → Nav3, поэтапно)

| Ветка | Что добавляется |
| --- | --- |
| `flow2/01-nav2-baseline` | Реалистичное многомодульное приложение на **Fragments + Navigation 2**, но каждый экран написан на Compose. Вложенный auth-флоу, нижний лист, диалог. |
| `flow2/02-nav3-catalog` | Миграция **первого целого модуля**: Каталог (список → товар **и** нижний лист фильтра) работает на локальном `NavDisplay` внутри одного Fragment; всё остальное остаётся на Nav2. |
| `flow2/03-nav3-auth-flow` | Замена **вложенной навигации** модуля (телефон → SMS → имя) на единый бэкстек `NavDisplay` внутри функционального модуля. |
| `flow2/04-unified` | Финальное состояние: **один корневой `NavDisplay`** на едином бэкстеке в обычном `ComponentActivity` — Fragment, FragmentManager и все XML-графы удалены. |
| `flow2/05-navgraph-plugin` | То же приложение в рантайме; добавляется [skydoves/compose-nav-graph](https://github.com/skydoves/compose-nav-graph) для генерации интерактивной карты всего флоу из нескольких аннотаций (для документации/визуализации, без изменения рантайма). |

Каждая ветка содержит собственный `BRANCH.md` с описанием: концепции, ключевого кода, **почему это важно**, **что ломается при старом подходе** и 🎤 **репликами для докладчика**. (`README.md` — это общий обзор, который без изменений присутствует в каждой ветке.)

## Рекомендуемый порядок показа

1. `main` — 30 секунд: «бэкстек — это список, которым вы владеете». Задаём контекст.
2. `flow1/01-basics` — весь API примерно в 15 строках. Добавьте пункт назначения вживую, чтобы показать, насколько это просто.
3. `flow1/02-scenes` — измените размер окна, чтобы включился многопанельный режим; откройте нижний лист.
4. `flow1/03-viewmodel-decorator` — самое тонкое место. Покажите утечку ViewModel, затем исправьте её одной строкой.
5. `flow1/04-animations` — нажмите на товар, чтобы получить **zoom** (переопределение для отдельной записи), откройте фильтр для **slide** (сцена): поведение по умолчанию vs. поведение для конкретного пункта назначения на одном экране.
6. *Передышка / Q&A.*
7. `flow2/01-nav2-baseline` — «вот наше реальное приложение». Указываем на боль Fragment + вложенных графов.
8. `flow2/02` → `03` → `04` — поэтапная миграция (первый модуль → auth-флоу → единый корень). Заканчиваем на едином корневом `NavDisplay`.
9. `flow2/05-navgraph-plugin` — опциональный финал: генерация аннотированной карты флоу, чтобы только что выстроенная навигация стала видимой и поддающейся ревью.

## Сборка

Откройте корень проекта в **Android Studio** (Narwhal или новее — требуется AGP 8.11 / Gradle 8.14 / тулчейн JDK 17, `compileSdk = 36`). Android Studio создаст jar-файл Gradle wrapper при первой синхронизации; если предпочитаете CLI, выполните `gradle wrapper` один раз в корне проекта, затем `./gradlew :app:assembleDebug`.

> В этом репозитории бинарный файл `gradle-wrapper.jar` **не зафиксирован** (только текстовая история для чистых диффов во время доклада). Версия Gradle зафиксирована в `gradle/wrapper/gradle-wrapper.properties`.

## Структура модулей (растёт от ветки к ветке)

```
app/                      ← хост Activity + корневая навигация
core/designsystem/        ← тема + простые цветные экраны Content() (чтобы ничто не отвлекало от навигации)
core/navigation/          ← общие типы NavKey (вводятся во флоу миграции)
feature/<name>/           ← один модуль на каждый функциональный модуль (catalog, auth, home, …)
```
